# A1 — `buggy-cli doctor`: preflight that says exactly what is missing

Epic: **E01** · Lane: **A** · Depends on: nothing

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Shannon has a `setup` wizard and `--validate-auth`; Xalgorix has `--setup`. Buggy fails late and cryptically (a missing token only shows up as a compose render error).

## Idea

One command that checks every prerequisite of `buggy hunt` and prints one line per check with a fix. Exit 0 when everything required passes, 2 otherwise.

## Architecture

New module `cli/doctor.py`. A check is a small function returning
`Check(name, status, detail, fix)` with `status` in `ok | warn | fail`. `run_checks(env, *, which, run, exists, free_port) -> list[Check]`
takes its side effects as injectable callables so tests never touch Docker.

Checks, in order:
1. `docker` binary found (`shutil.which`).
2. `docker compose version` returns v2+ (parse `v2.x`).
3. Docker daemon reachable (`docker info --format {{.ServerVersion}}`).
4. Required secrets non-empty in the env mapping: `SANDBOX_TOKEN`, `EGRESS_GUARD_TOKEN`, `BUGGY_STACK_MCP_TOKEN`. Fix text: `scripts/ensure-stack-secrets.sh`.
5. Images present for the profile (`docker image inspect <name>`): lite = `buggy-pipeline:stable`; full adds `buggy-langgraph, buggy-litellm, buggy-sandbox, buggy-egress-guard, buggy-browser, buggy-skillogy` (tag `${BUGGY_VERSION:-stable}`). Missing = fail with fix `make build-images`.
6. Host ports free: 2024, 4000, 7474, 7687 (full profile only; honour `LANGGRAPH_PORT`, `LITELLM_PORT`, `NEO4J_HTTP_PORT`, `NEO4J_BOLT_PORT`). In use = fail naming the variable to change.
7. `BUGGY_HOME` (default `~/.buggy`) writable; create `workspace`, `control`, `audit` if absent.
8. Free disk at `BUGGY_HOME` >= 10 GB (warn below 20 GB), total RAM >= 8 GB for full (warn).
9. Model configured (reuse `buggy.cli.hunt.model_configured`): warn only, with text "recon and report still work; agents need a model".

CLI: `buggy-cli doctor [--profile lite|full] [--json]`. Human output is an aligned table with `ok / warn / FAIL`; `--json` prints `{"ok": bool, "checks": [...]}`. Env comes from `os.environ` overlaid on a `.env` in the current directory if present (parse `KEY=VALUE`, ignore comments).

## Files you own

- packages/buggy/buggy/cli/doctor.py (new)
- packages/buggy/tests/unit/cli/test_doctor.py (new)

## Out of scope

Starting or pulling anything. Editing compose files, the launcher, or `cli/__main__.py`.

## Tests that must exist and pass

`test_doctor.py`, all with injected fakes:
- every check passes -> exit 0, `ok: true`.
- each failure in isolation (no docker, compose v1, daemon down, each missing secret, missing image, busy port, unwritable home) -> exit 2 and the fix text names the exact remedy.
- lite profile does not require the full-profile images or ports.
- a missing model is a warning and does not change the exit code.
- `--json` is valid JSON with one entry per check, in order.
- `.env` values are read, and real environment variables win over them.

## Done when

`uv run buggy-cli doctor --json` runs on this machine and reports truthfully.
