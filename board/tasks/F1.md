# F1 — Lessons: what worked and what failed, kept across engagements

Epic: **E07** · Lane: **F** · Depends on: nothing

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

PentAGI separates per-run memory from reusable `guide` / `answer` / `code` knowledge, retrieved by similarity (threshold 0.7, limit 3); RedAmon's EvoGraph loads prior findings and failure lessons into new sessions. Buggy's agents start every engagement from zero.

## Idea

A small cross-engagement store of lessons, retrieved by technology and class, where only lessons tied to a verified finding count as trusted.

## Architecture

New package `buggy/memory/` (stdlib only): `lessons.py`.
- SQLite file `lessons.sqlite3` with FTS5 (check `sqlite3` FTS5 availability at open; if missing, fall back to `LIKE` search and expose `fts: false`).
- `Lesson`: `id, kind (guide|failure|payload), title, body (<= 2000 chars), classes [..], technologies [..] (lower-case names such as "express", "graphql", "jwt"), source_engagement, finding_id (optional), trust (verified|unverified), created_at, uses, last_used_at`.
- `LessonStore.save(lesson, actor) -> id`: `trust` is `verified` only when the caller passes `verified_finding=True` (the integrator sets it from the findings store; an agent can never set it); body is passed through `scrub()` which removes anything that looks like a credential (Bearer tokens, JWTs, `password=`, API-key shapes, cookies) and replaces target hostnames from the source engagement's scope with `<target>` — lessons must be about technique, not about a customer.
- `search(query="", *, classes=(), technologies=(), kind=None, limit=3, include_unverified=False) -> list[dict]`: rank = FTS bm25 (or LIKE hit count) + 2 per matching technology + 1 per matching class + 1 if verified; ties by recency. Default returns verified only. Each returned lesson increments `uses`.
- `for_engagement(technologies, classes, limit=5)`: the briefing set for a new engagement (technologies come from recon `technology` records).
- Size limits: 5,000 lessons, oldest unverified evicted first.
Returns JSON-serialisable dicts everywhere.

## Files you own

- packages/buggy/buggy/memory/__init__.py, lessons.py (new)
- packages/buggy/tests/unit/memory/test_lessons.py (new)

## Out of scope

Vector embeddings, external services, MCP registration, prompt injection of lessons into agents (integrator).

## Tests that must exist and pass

- save/search round trip; ranking: a verified GraphQL lesson outranks an unverified one for `technologies=["graphql"]`; default search hides unverified.
- scrubbing: tokens, JWTs, passwords, cookies and the source scope's hostnames never survive in a stored lesson (search the DB file bytes for the fixture secrets).
- an agent-supplied `trust: "verified"` field is ignored.
- limit and eviction.
- FTS fallback path (force it) returns the same top result for a simple query.
