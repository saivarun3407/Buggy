# D3 — Evidence bundle: a reproducible package per finding

Epic: **E06** · Lane: **D** · Depends on: D2

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

CyberStrikeAI offers step-by-step replay of an attack chain; Shannon keeps a scratchpad of scripts and screenshots per finding. A bounty triager wants a request they can paste. Buggy records everything but cannot hand it over in a standard form.

## Idea

Export the captures behind a finding as a self-checking bundle: HAR, curl commands, and a manifest with hashes.

## Architecture

New module `capture/export.py`:
- `to_har(captures: list[Capture], *, redact=True) -> dict` — HAR 1.2 (`log.version`, `creator`, `entries[]` with request method/url/headers/postData and response status/headers/content.text, `startedDateTime`, `time`). With `redact=True`, values of sensitive headers and cookies are `<redacted>` and bodies are kept.
- `to_curl(capture, *, redact=True) -> str` — one POSIX `curl` command with `--request`, `--header` per header, `--data-binary` (shell-quoted with `shlex.quote`), `--max-redirs 0`; redacted headers become `-H 'Authorization: <AUTHORIZATION>'` placeholders listed at the top as variables to fill.
- `bundle(gateway_store, engagement, capture_ids, *, finding: dict | None, ledger_path: Path | None) -> dict[str, bytes]` returning files: `evidence.har`, `reproduce.sh` (curl commands in order, with comments naming each step from the capture `note`), `captures.json` (summaries + response sha256), `ledger-excerpt.jsonl` (the ledger lines whose `capture_id` is in the set, verbatim), `MANIFEST.json` (`{file: sha256}` for every other file, plus engagement, created_at, capture ids, tool version).
- `verify_bundle(files) -> list[str]` returns mismatches (empty = intact).
Unknown capture id -> `KeyError` naming it. Captures from another engagement are refused.

## Out of scope

Zipping/writing to disk policy, MCP tool, CLI (integrator wires `evidence_export`).

## Tests that must exist and pass

- HAR validates structurally (required keys per HAR 1.2) and round-trips a POST with a JSON body and a binary response.
- curl output executes correctly: run the generated command against a local `http.server`-based echo server started in the test and assert the server received the same method, path, headers and body (this proves quoting; include a body with quotes, newlines and `$`).
- redaction: fixture secrets never appear in any bundle file when `redact=True`.
- manifest hashes verify; flipping one byte is detected.
- cross-engagement capture id is refused.

## Done when

Tests pass, including the real-curl round trip.
