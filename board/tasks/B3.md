# B3 — Parameter records: every input the target accepts, as data

Epic: **E02** · Lane: **B** · Depends on: B2

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

RedAmon's graph has `Parameter` nodes (Arjun, ParamSpider, crawl); Shannon's analysis lists sinks per parameter. Buggy stores URLs and API operations but not their parameters, so 'which inputs take a URL / an id' has to be re-derived by an agent every time.

## Idea

Extract parameters deterministically from what the pipeline already collected and store them as first-class records.

## Architecture

1. `pipeline/schema.py`: add `RecordType.PARAMETER = "parameter"`. Record: `asset` = host, `value` = `<METHOD> <url without query> <location>:<name>`, attrs `{name, location: query|path|body|header|cookie|form, method, url, example, sources: [...], hints: [...]}`.
2. New builtin tool `pipeline/tools/params.py` (no network): `extract(records: Iterable[StoredRecord]) -> Iterator[Record]` from:
   - `url` / `endpoint` records: query-string names (keep one example value, truncated to 80 chars);
   - path segments that look like identifiers (digits, UUID, 24-hex) -> location `path`, name = previous segment + `_id`;
   - `api_operation` records: `attrs.parameters` (name, in) and JSON body schema property names when present;
   - HTML forms are out of scope unless a `form` list is already in a record's attrs.
   `hints` is computed by fixed rules: `id-like` (name matches `^(id|.*_id|uuid|.*Id)$` or path id), `url-like` (name in url, uri, callback, webhook, redirect, next, dest, return, image_url, fetch, proxy, or example starts with http), `file-like` (file, path, filename, template, page, include), `numeric` (example parses as number), `auth-like` (token, jwt, session, api_key, key).
3. `pipeline.py`: run it at the end of the `apispec` stage over the stage's hosts; store with tool name `params`, version `builtin-1`. Cached with the stage.
4. `pipeline/report.py::rank_candidates`: use parameter hints instead of re-parsing URLs for the `ssrf` and `access_control` rows, and add a `file_handling` row for `file-like` parameters (probe: `path_traversal`).
5. `query.py`: nothing new needed (`recon_query record_type=parameter` works once the type exists); make sure the type list includes it.

## Out of scope

Active parameter brute-forcing (Arjun-style guessing). Any new network requests.

## Tests that must exist and pass

- fixture records -> expected parameter set with locations and hints (table-driven, at least 12 cases, including a UUID path id, a nested OpenAPI body property, and a query param with an http example).
- no parameters from static assets (`.js`, `.css`, images) — negative control.
- the same parameter seen from two sources is one record with both sources.
- secrets are not stored: an example value for an `auth-like` parameter is replaced by `<redacted>`.
- report candidates: an `image_url` body parameter yields an `ssrf` candidate; a `file` query parameter yields a `file_handling` candidate; a parameter named `q` yields nothing.

## Done when

Pipeline and report tests green.
