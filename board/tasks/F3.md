# F3 — Benchmark evidence contract: results anyone can check

Epic: **E08** · Lane: **F** · Depends on: F2

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

RedAmon publishes per-target raw sessions, model, wall time and tokens for its XBOW run (but not the mapping needed to re-verify, and its failed rows have no logs). PentestGPT labels its 86.5% as historical. Buggy removed an unsound score and has nothing to replace it with. When a real run happens it must be auditable from the published files alone.

## Idea

Define and implement the record every benchmark run must produce, a scorecard generated only from those records, and a verifier a third party can run.

## Architecture

New `benchmark/evidence.py` and `benchmark/scorecard.py` (read `benchmark/providers/xbow.py`, `benchmark/schemas.py`, `benchmark/runner.py` first; the XBOW provider already builds each challenge with a fresh random flag).
- `RunRecord` (one JSON file per target per attempt under `benchmark/results/<run-id>/<target>.json`): `run_id, target, suite, attempt, started_at, finished_at, wall_seconds, model (provider/model id), model_profile, git_revision, image_digests {name: digest}, black_box_inputs (exact list of what the solver was given), flag_commitment (sha256 of the random flag, written BEFORE the attempt starts), flag_revealed (the flag, written after), solved: bool, win_evidence {transcript_file, line, sha256_of_line}, tokens {input, output}, cost_usd, terminal_state (solved|gave_up|timeout|error), error, transcript_file (raw, unedited JSONL), transcript_sha256`.
- `commit_flag(flag) / check_commitment(record)`; `write_record` refuses to write `solved: true` unless the revealed flag hashes to the commitment AND the flag string occurs in the transcript file at the cited line.
- `verify_run(directory) -> list[Problem]`: for every record re-checks commitment, transcript hash, flag-in-transcript; reports missing transcripts, duplicate targets, records without a failure reason. Exit non-zero from `python -m benchmark.evidence verify <dir>` when anything fails.
- `scorecard.render(directory) -> str` (Markdown): header with run id, date, revision, model, black-box statement; one row per target INCLUDING failures: `target | level | solved | wall s | in tokens | out tokens | cost | transcript`; totals; "not attempted" targets listed by id; no row without a record. `python -m benchmark.scorecard <dir> [--write]`.
- A `RESULTS_POLICY.md` in `benchmark/` (short): a number may appear in the README only with a link to a run directory that passes `verify`; historical numbers are labelled historical.
- Wire `benchmark/providers/xbow.py` to emit the commitment before the solver starts and the record after (minimal change; keep its tests passing).

## Files you own

- benchmark/evidence.py, benchmark/scorecard.py, benchmark/RESULTS_POLICY.md (new)
- benchmark/providers/xbow.py (emit records only)
- packages/buggy/tests/unit/benchmark/test_evidence.py, test_scorecard.py (new)

## Out of scope

Running any benchmark (no model credentials here). Changing how challenges are solved.

## Tests that must exist and pass

- a solved record with a correct commitment and the flag in the transcript verifies.
- tampering is caught: changed flag, changed transcript byte, `solved: true` without the flag in the transcript, a commitment written after the reveal (timestamps), a missing transcript.
- `write_record` refuses an unsupported `solved: true`.
- scorecard includes failed and not-attempted targets and its totals equal the records.
- the provider emits a commitment before solving (assert ordering with a fake solver).
- existing benchmark tests still pass.

## Done when

Benchmark unit tests green; `python -m benchmark.evidence verify` on a fixture run directory returns 0, and 1 on a tampered copy.
