# E5 — SARIF 2.1.0, a CI gate, and a GitHub Action

Epic: **E11** · Lane: **E** · Depends on: E4

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Shannon: `KeygraphHQ/shannon-action@v1` with `fail-on-severity` and `upload-sarif`, counting only `status: exploited`, and separating an incomplete run from a clean one. Strix `-n` exits non-zero on findings. Buggy has no CI story.

## Idea

Three thin pieces over the report JSON so a pipeline can gate on verified findings and upload them to code scanning.

## Architecture

1. `findings/sarif.py`: `to_sarif(report: dict, *, tool_version) -> dict` — SARIF 2.1.0: one `run`, `tool.driver.name = "Buggy"`, `rules` one per class (`buggy/<class>`, with `shortDescription`, `helpUri` to the CWE), `results` only for exploit_verified findings: `ruleId`, `level` (critical/high -> error, medium -> warning, low/info -> note), `message.text` (title + endpoint), `locations` (`physicalLocation.artifactLocation.uri` = endpoint URL as required by code scanning for DAST results; also `properties.method`, `properties.parameter`), `partialFingerprints.findingId` = finding id, `properties.security-severity` numeric (critical 9.5, high 8.0, medium 5.5, low 3.0, info 0.0).
2. `cli/ci_gate.py`: `buggy-cli ci-gate --report <report.json> [--hunt-result <hunt-result.json>] [--fail-on high] [--sarif out.sarif]`. Exit codes: 0 complete and below threshold; 10 at/above threshold; 3 incomplete (report `summary.complete` false or hunt-result `complete` false) — incomplete wins over clean, vulnerable wins over incomplete; 2 bad input. Prints one summary line and the list of gating findings. Writes SARIF when asked.
3. `.github/actions/buggy-scan/action.yml` (composite): inputs `report`, `hunt-result`, `fail-on` (default `high`), `upload-sarif` (default `true`); steps: run `buggy-cli ci-gate`, then `github/codeql-action/upload-sarif` when enabled (document the required `security-events: write` permission). Plus `docs/ci.md` with a complete example workflow that runs `buggy hunt --lite ... --fail-on high` against a staging URL and then the action.

## Tests that must exist and pass

- SARIF structure: required top-level keys, `version` "2.1.0", `$schema`; every result references an existing rule; only verified findings appear; validate against a vendored minimal JSON-schema subset or assert the required-field set explicitly.
- gate exit-code matrix (clean, vulnerable at threshold, below threshold, incomplete, incomplete+vulnerable, malformed input).
- `action.yml` parses as YAML and declares the inputs; the example workflow in `docs/ci.md` parses as YAML.

Tests pass.
