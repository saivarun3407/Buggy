# B4 — Operator-supplied API contracts (OpenAPI, Postman)

Epic: **E09** · Lane: **B** · Depends on: B3

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Strix takes an OpenAPI/Swagger file or a Postman export so every declared endpoint is tested, not only what a crawler finds. Buggy only finds specs the target publishes.

## Idea

Let the operator hand the pipeline a contract; treat it as input data, scope-filtered like everything else.

## Architecture

1. Scope document: `pipeline.api_contracts: [{"path": "<file under control/<engagement>/contracts/>", "base_url": "<optional override>", "format": "openapi|postman|auto"}]`. Parse in `pipeline/scope.py::PipelineLimits.from_roe` as `api_contracts: tuple[dict, ...]` (max 10; reject paths with `..` or absolute paths).
2. New `pipeline/tools/contracts.py`: `load(control_dir, entry) -> list[Record]`:
   - OpenAPI 2/3 JSON or YAML: reuse the existing parser in `pipeline/tools/apispec.py` (read it first; factor a shared function if needed without changing its behaviour) to emit `api_spec` + `api_operation` records, with `attrs.source = "operator"`.
   - Postman v2.1 collection JSON: walk `item` recursively; each request -> `api_operation` (method, url with `{{var}}` resolved from collection `variable` list, header names, body mode + raw JSON property names). Never store header values or auth blocks.
   - every operation URL is passed through `scope.admit(..., stage="apispec", tool="contracts", direction="input")`; out-of-scope operations are dropped and logged.
3. `pipeline.py`: at the start of the `apispec` stage, load contracts (content hash is the cache key, so an unchanged file is not re-read).
4. `cli/scope.py`: nothing. Document the block in `docs/pipeline.md` (append a short section).

## Out of scope

Fetching contracts from URLs. A CLI to upload them.

## Tests that must exist and pass

- each fixture yields the expected operations (assert method, URL, parameter names, auth_required).
- operations on an out-of-scope host in the contract are dropped and logged, never stored.
- Postman variables resolve; an unresolved variable leaves the operation out with a logged reason.
- no header value, token or password from a fixture appears in any record (fixtures contain fake secrets to prove it).
- path traversal in `path` is rejected at scope load.
- unchanged contract on a second run is cached.
