# D4 — Notifications: tell the operator when something waits for them

Epic: **E04** · Lane: **D** · Depends on: D3

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Xalgorix notifies over Discord and Telegram; Strix Cloud over Slack. Buggy holds state-changing requests for approval but the operator only finds out by running `approvals list`.

## Idea

A small outbound-only notifier for four events, configured by the operator, with no secrets in agent reach.

## Architecture

New module `buggy/notify.py` (stdlib only):
- Config from env (operator side / service env, never the sandbox): `BUGGY_NOTIFY_WEBHOOK_URL` (generic JSON POST), `BUGGY_NOTIFY_SLACK_WEBHOOK_URL`, `BUGGY_NOTIFY_DISCORD_WEBHOOK_URL`, `BUGGY_NOTIFY_EVENTS` (comma list, default all), `BUGGY_NOTIFY_MIN_INTERVAL_SECONDS` (default 30, per event type + engagement).
- `Event(kind, engagement, title, detail, fields: dict, at)` with `kind` in `approval_required | recon_finished | finding_verified | run_failed`.
- `Notifier.from_env(opener=urllib.request.urlopen)`; `notify(event) -> list[Delivery]`; formats: generic `{kind, engagement, title, detail, fields, at}`; Slack `{"text": ...}` (mrkdwn, one line title + bullets); Discord `{"content": ...}` (<= 1900 chars).
- Never raises to the caller: failures are returned as `Delivery(ok=False, error=...)` and logged; timeouts 5 s; rate limit drops duplicates inside the interval and counts them.
- Privacy rule enforced in code: an event may contain method, URL host + path, request id, severity, class, counts. It must NOT contain bodies, header values, tokens or query strings: `sanitize_url(url)` strips query and fragment; `Event` rejects `fields` keys named like secrets.
- Hook points as functions only (do not edit other modules): `approval_event(request_record)`, `recon_event(summary)`, `finding_event(finding)`, `failure_event(engagement, stage, error)` build the right `Event` from the existing record shapes (approval request records in `capture/gateway.py::_check_approval`, `recon_summary`, the Finding contract).

## Files you own

- packages/buggy/buggy/notify.py (new)
- packages/buggy/tests/unit/test_notify.py (new)

## Out of scope

Email, Telegram bots, inbound commands (approving from chat). Calling the notifier from other modules (integrator).

## Tests that must exist and pass

- each sink receives the right payload shape (fake opener capturing requests).
- a sink failure or timeout does not raise and does not stop the other sinks.
- rate limit: 5 identical events in a second -> 1 delivery, 4 suppressed, counted.
- privacy: an approval record whose URL has `?token=SECRET` and whose body preview contains a password produces a notification containing neither (search the serialized payloads).
- event filter via `BUGGY_NOTIFY_EVENTS`.
- no configuration -> `notify` is a no-op returning an empty list.

## Done when

Tests pass.
