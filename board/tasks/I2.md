# I2 — Integration: images, compose, secrets root, docs

Epic: **INT** · Lane: **I** · Depends on: I1

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

New modules must exist in the slim images and the secrets root must be mounted only where it belongs.

## Idea

Ship it: Dockerfiles, compose services and invariants, env examples, documentation.

## Architecture

- `containers/pipeline.Dockerfile` / `browser.Dockerfile`: COPY `findings`, `memory`, `coordination`, `notify.py`, `program`, `cli`.
- `docker-compose.yml`: `${BUGGY_HOME}/secrets:/secrets:ro` on `capture-mcp` and `browser-mcp` only; operator gets it read-write; notifier env on capture-mcp/pipeline; `BUGGY_MCP_CAPTURE_URL` for the operator.
- `tests/test_compose_network_isolation.py`: secrets root is never mounted into `sandbox`, `langgraph`, `pipeline-mcp`, `scope-mcp`.
- Docs: quickstart, evidence-and-probes, bounty-programs, pipeline, a new `docs/findings.md`; update the evaluation matrix with what is now verified.

New features.
