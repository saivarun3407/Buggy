# C4 — Open redirect, path traversal and CORS probes

Epic: **E09** · Lane: **C** · Depends on: C3

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Xalgorix has phases for open redirect and CORS; Juice Shop has a known open redirect and a null-byte file read in the lab ground truth that Buggy cannot find deterministically.

## Idea

Three small read-only probes for classes that are decided by one or two responses.

## Architecture

Follow the existing pattern exactly: a function `name(ctx: Context, params: dict) -> ProbeResult` in a new module under `capture/probes/`, registered with a `ProbeSpec` in `capture/probes/registry.py` (add your entries at the end of the tuple; import your module at the top). All requests go through `ctx.send`. Verdict rules that apply to every probe:
- `vulnerable=True` only with a control that rules out coincidence (stated per probe below).
- `vulnerable=None` ("could not tell") when the baseline request fails, the gateway refuses, or signals conflict. Never guess.
- `evidence` lists the capture ids of baseline, control and proof requests; `details` names which is which.
- `remediation` is specific to the class.
- Payload lists are short and fixed (constants in the module). No destructive payloads: nothing that writes, deletes, sleeps longer than the stated bound, or reads files other than the stated markers.

Module `capture/probes/misc.py`.
`open_redirect` (class `open_redirect`, CWE-601): params `url`, `parameter`, `location`, `value`, `headers`, optional `allowlist_hint`. Send the parameter set to `https://<random>.example/` (reserved TLD, never resolved by us — the gateway does not follow redirects). Vulnerable when the response is 3xx with `Location` whose host is that random host, or a 200 whose body has a meta refresh / `window.location` to it. Then try at most 4 fixed bypass forms only if the plain form is refused (`//host`, `https:host`, `https://allowed@host`, `https://host#allowed`). Control: the original value must not already redirect off-site.
`path_traversal` (class `file_handling`, CWE-22): params as above. Read-only markers only: request `../` chains (depth 2..6, plain and URL-encoded, with and without a `%00` + original extension suffix) for exactly two well-known world-readable files: `etc/passwd` (marker regex `root:.*:0:0:`) and `windows/win.ini` (marker `[fonts]`). Max 10 requests. Vulnerable when a marker appears and the baseline response does not contain it.
`cors` (class `misconfiguration`, CWE-942): params `url`, `headers`. Three GETs with `Origin: https://<random>.example`, `Origin: null`, and no Origin. Vulnerable when ACAO reflects the random origin (or is `null`) AND `Access-Control-Allow-Credentials: true`; report `wildcard-without-credentials` as informational (`vulnerable=False`, noted in details).

## Out of scope

Following redirects to third parties. Reading any file other than the two markers. Writing files.

## Tests that must exist and pass

Unit: each probe against vulnerable and safe fakes, including: a redirect to a same-site path (False), an allowlist that only the `@` form bypasses (True, technique reported), traversal blocked by normalisation (False), a page that always contains `root:x:0:0:` (control -> False), CORS reflecting with and without credentials.
Lab: Juice Shop `/redirect?to=` — the app allow-lists some URLs; the probe must find the known bypass or report False honestly (document which). Juice Shop `/ftp/` null-byte read (`/ftp/eastere.gg%2500.md`) is a file-type bypass, not a traversal to `/etc/passwd`: assert the probe reports False/None there and say so in the report — do not stretch the probe to claim it.

## Done when

Unit and lab tests pass; the report states what the lab could and could not confirm.
