# F6 — Run telemetry and a loop guard: see cost and stop wasted work

Epic: **E12** · Lane: **F** · Depends on: F5

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

PentAGI monitors execution (5 identical or 10 total tool calls trigger a mentor intervention; hard per-role tool-call caps) and traces every LLM and tool call (Langfuse, OpenTelemetry). Buggy has a budget middleware but no per-run view of calls, tokens and cost, and nothing that notices an agent repeating itself.

## Idea

Count what a run does, expose it, and intervene deterministically when an agent loops.

## Architecture

1. New `middleware/loop_guard.py` (read `middleware/budget.py` and one small existing middleware for the `AgentMiddleware` hook shapes used in this repo; follow them exactly):
   - Tracks, per run (thread id from the runtime/config) and per agent role: a rolling window of the last 20 tool calls as `(tool_name, sha256(canonical JSON args))`.
   - Identical call repeated `>= 3` times in the window, or the same tool `>= 8` times with pairwise argument similarity >= 0.9 (difflib ratio on canonical JSON): the NEXT such call is not executed; the tool message returned says: this exact call has been made N times with the same result; state what you expected to change, or try a different approach; lists the last distinct results' summaries (first 200 chars each).
   - Hard cap per role per run from env `BUGGY_MAX_TOOL_CALLS_<ROLE>` / `BUGGY_MAX_TOOL_CALLS` (default 300): beyond it every tool call returns a "budget exhausted, write up what you have" message.
   - Thresholds configurable by constructor; state is in-memory and bounded (max 500 runs, LRU).
   - Never blocks tools named in an allowlist (`report_record_finding`, `finding_submit`, `scope_show`, `recon_summary`).
2. New `telemetry_run.py` (in `buggy/`): `RunCounters` — thread-safe per-run counters fed by the loop guard: tool calls by tool and by role, blocked-by-loop count, refusals; `snapshot(run_id) -> dict`; written as JSON lines to `audit/<engagement>/run-telemetry.jsonl` every 30 s and at run end (append-only, one line per snapshot). Token and cost numbers are NOT invented here: add a `spend(litellm_url, key, since) -> dict | None` helper that reads LiteLLM's spend endpoint the way `benchmark/lab/agent.py::spend_between` does (reuse/import that logic; if unreachable return None).
3. Register nothing globally: expose `make_loop_guard(role)` and document in the module docstring where the integrator adds it in `agents/middleware_slots.py`.

## Out of scope

Editing `middleware_slots.py`, the budget middleware, or agent prompts. OpenTelemetry/Langfuse exporters.

## Tests that must exist and pass

- identical call 3x -> the 4th is intercepted with the explanatory message and the handler is not called; a different call in between resets nothing but is itself executed.
- near-identical arguments (one changing counter field) trip the similarity rule at 8; genuinely different arguments never do (negative control with 30 distinct calls).
- allowlisted tools are never blocked.
- hard cap message after the limit; per-role env override.
- sync and async paths both covered (the repo's middlewares implement both).
- counters: snapshot content and the JSONL writer (append-only, valid JSON per line, bounded memory with 600 simulated runs).
- `spend` returns None on connection error.

## Done when

Middleware and telemetry tests green; existing middleware suite still green.
