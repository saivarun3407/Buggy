# C3 — Server-side template injection and OS command injection probes

Epic: **E09** · Lane: **C** · Depends on: C2

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Strix and Xalgorix list SSTI, command injection and RCE; DVGA has two command-injection bugs Buggy cannot find deterministically.

## Idea

Two bounded probes that confirm evaluation or execution with arithmetic and timing canaries, never by running anything harmful.

## Architecture

Follow the existing pattern exactly: a function `name(ctx: Context, params: dict) -> ProbeResult` in a new module under `capture/probes/`, registered with a `ProbeSpec` in `capture/probes/registry.py` (add your entries at the end of the tuple; import your module at the top). All requests go through `ctx.send`. Verdict rules that apply to every probe:
- `vulnerable=True` only with a control that rules out coincidence (stated per probe below).
- `vulnerable=None` ("could not tell") when the baseline request fails, the gateway refuses, or signals conflict. Never guess.
- `evidence` lists the capture ids of baseline, control and proof requests; `details` names which is which.
- `remediation` is specific to the class.
- Payload lists are short and fixed (constants in the module). No destructive payloads: nothing that writes, deletes, sleeps longer than the stated bound, or reads files other than the stated markers.

Module `capture/probes/execution.py`.
`ssti` (class `injection`, CWE-1336): params as in `sqli`. Pick two random 4-digit integers a, b. Send, per engine family, one arithmetic canary: `{{a*b}}`, `${a*b}`, `<%= a*b %>`, `#{a*b}`, `{a*b}` (5 requests max). Vulnerable when the product `a*b` appears in the response AND the literal payload text does not, AND a control request with `{{a*b}}` replaced by the plain digits of a different random number does not coincidentally contain the product. Report `engine_family`.
`command_injection` (class `injection`, CWE-78): params as in `sqli`, plus `allow_time` (default true). Two techniques:
 - output: append separators with an arithmetic echo, e.g. `;echo $((a*b))`, `|echo $((a*b))`, `` `echo $((a*b))` ``, `$(echo $((a*b)))`, `& set /a a*b` (max 5). Vulnerable when the product appears and the payload text does not.
 - time: `;sleep 3`, `|sleep 3`, `& ping -n 4 127.0.0.1` (max 3), with the same baseline/control timing rule as `sqli` (>= baseline + 2.5 s and zero-delay control within + 1 s).
 State-changing flag: True (a shell is being asked to run something), so real programs require approval.
Both: baseline twice first; unstable -> `None`.

## Out of scope

Reading files, spawning shells, out-of-band callbacks, any payload beyond echo/sleep/ping-localhost.

## Tests that must exist and pass

Unit: fake endpoints that evaluate Jinja-style / EL-style expressions, that pass input to a simulated shell (echo + sleep via injected clock), that reflect the payload verbatim (must be False), that already contain the product by chance on every response (control must stop a false positive), unstable (`None`).
Lab: DVGA `importPaste` mutation (host/path/scheme arguments reach a shell) and `systemDiagnostics` — target the GraphQL endpoint with `location=json` on the variable carrying the argument; at least one of the two must be found; DVGA `pastes` query filter must NOT be flagged as command injection (negative control). If DVGA is in hardened mode the fixture resets it with `GET /difficulty/easy`.

## Done when

Unit and lab tests pass.
