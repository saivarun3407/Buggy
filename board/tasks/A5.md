# A5 — `hunt`: resume, exit codes for CI, and a machine-readable result file

Epic: **E01** · Lane: **A** · Depends on: A2

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Shannon resumes a scan by reusing `-w <name>` and separates incomplete from clean in CI; Strix `-n` exits non-zero on findings. `hunt` always exits 0 and rewrites the scope on every call.

## Idea

Make `hunt` safe to re-run and usable as a gate.

## Architecture

Edit `cli/hunt.py` only.
1. Resume: if `control/<engagement>/roe.json` already exists for the given `--engagement-name`:
   - compute the scope the command line would write; if its `machine_enforcement` + `pipeline` + `approvals` + `network` blocks equal the stored ones, do not rewrite, do not prompt, print `resuming <name>`;
   - if they differ, print a field-by-field diff and require confirmation (`--yes` accepts); never silently widen scope.
   - `--resume <name>` is a shorthand that takes targets and all options from the stored `roe.json` (store the original argv-derived settings under a top-level `hunt` key when first written: targets, rps, flags) so `buggy hunt --resume acme` needs nothing else.
2. Result file: at the end of every run write `control/<engagement>/hunt-result.json`: `{engagement, finished_at, recon: {state, records, scope_drops}, issues: {critical..info}, findings: {exploit_verified: n by severity, inconclusive, candidates}, approvals_pending, agent: {ran, error}, complete: bool}`. `complete` is false when recon timed out / failed, or the agent stage errored.
3. Exit codes (documented in `--help`): `0` complete and nothing at or above the threshold; `10` complete and something at or above `--fail-on` (default: never fail); `3` incomplete; `2` usage/config. `--fail-on {critical,high,medium,low,info}` counts exploit-verified findings and, with `--fail-on-issues`, known issues from the recon report too.
4. Findings counts come from `buggy.cli.status.snapshot` (task A2); if that section is unavailable treat counts as zero and set `complete` accordingly only for recon/agent failures.

## Files you own

- packages/buggy/buggy/cli/hunt.py
- packages/buggy/tests/unit/cli/test_hunt.py (extend; keep existing tests passing)

## Out of scope

Launcher flags. The findings store. Anything in `pipeline/`.

## Tests that must exist and pass

- resume with identical settings writes nothing new (file mtime unchanged) and does not prompt.
- resume with a changed scope shows the diff and is refused without confirmation.
- `--resume name` reproduces the original targets and options.
- exit code matrix: clean -> 0; high issue with `--fail-on high --fail-on-issues` -> 10; recon timeout -> 3; agent error -> 3; bad pattern -> 2.
- `hunt-result.json` content for each of those cases.

## Done when

All existing hunt tests plus the new ones pass.
