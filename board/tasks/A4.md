# A4 — Launcher: `buggy hunt --lite`, `buggy doctor`, `buggy demo`

Epic: **E01** · Lane: **A** · Depends on: A1, A3

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Shannon's value is two commands to a report. The launcher currently requires model auth and the full stack even for a recon-only run, and there is no bundled target to try it on.

## Idea

Three small launcher additions so a new user can go from install to a real recon report without a model key, against a target that ships with the tool.

## Architecture

Go, in `clients/launcher`:
1. `internal/compose`: add `NewWithFile(path string)` (or an option) so a command can use `docker-compose.lite.yml` from the Buggy home. Add the lite file to whatever list the updater syncs/checksums next to `docker-compose.yml` (search for `docker-compose.tun.yml` to find every place: updater file list, release workflow checksum line).
2. `cmd/hunt.go`: flag `--lite`. With `--lite`: skip `config.ValidateAuth`, force `--no-agent`, start only `pipeline` and `pipeline-mcp` from the lite file, run `operator` from the lite file. Factor `prepareStack` minimally: extract the auth validation into a function that `--lite` skips; do not change behaviour without the flag.
3. `cmd/doctor.go`: `buggy doctor [--profile lite|full] [--json]` runs `buggy-cli doctor` in the operator container when images exist, and otherwise prints the three host checks itself (docker binary, compose v2, daemon) with the same wording.
4. `cmd/demo.go`: `buggy demo` starts `juice-shop` from `docker-compose.lab.yml` together with the lite stack (the pipeline must join `lab-net` and get `BUGGY_PIPELINE_DNS_RESOLVERS=127.0.0.11:53`; write a `docker-compose.demo.yml` overlay for that) and runs `hunt http://juice-shop.lab:3000 --lab --no-agent --yes --rps 50 --engagement-name demo`. Print where the report is. `buggy demo --down` removes it.

Keep each command's flag wiring in the style of `cmd/hunt.go`.

## Tests that must exist and pass

- Go unit tests: `--lite` builds the expected operator argv (contains `--no-agent`, uses the lite file) and does not call auth validation; without `--lite` the argv is unchanged from today (golden test).
- `demo` builds the expected compose file list and hunt argv; `--down` builds the down command.
- `go build ./... && go vet ./... && go test ./...` all pass (they pass today).
- `tests/test_compose_demo.py`: lite + lab + demo overlay renders; pipeline is on `lab-net`; juice-shop has no published port and is on the internal network only.
