# C5 — Coverage audit: one explicit verdict per vulnerability class and known bug

Epic: **E08** · Lane: **C** · Depends on: C4

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

RedAmon publishes a self-critical coverage audit: every class is complete, backlog or excluded. Its published buckets do not sum to the total; ours must.

## Idea

A generated, checkable statement of what Buggy can and cannot find deterministically, so nobody (including us) overstates it.

## Architecture

1. Update `benchmark/lab/ground_truth/*.json`: set `verified_by` for every entry a lab test now proves (from C1–C4 and the existing tests), using the exact pytest node id. Do not set it for anything a test does not assert.
2. New `benchmark/lab/coverage.py`: `audit(apps) -> dict` computing, per class in `taxonomy.CLASSES` and per ground-truth entry, exactly one verdict:
   - `proven` — `verified_by` names a test that exists (check the file and function name exist on disk);
   - `pipeline` — matched only by `pipeline_signals`;
   - `backlog` — no deterministic coverage;
   - `excluded` — `prohibited` (DoS etc.), with the reason.
   Invariant enforced in code: the four buckets sum to the number of entries, per class and overall; raise if not.
3. CLI: `python -m benchmark.lab coverage [--apps ...] [--write]` prints a Markdown table (class x verdict counts, then the backlog list by id) and with `--write` saves `benchmark/lab/results/coverage.md` with the date and the git revision.
4. Regenerate `benchmark/lab/results/coverage.md` and update the probes column in `benchmark/lab/results/README.md` to the new numbers. Keep the "agent arms: not run" statement.

## Files you own

- benchmark/lab/coverage.py (new)
- benchmark/lab/__main__.py (add the subcommand)
- benchmark/lab/ground_truth/*.json
- benchmark/lab/results/coverage.md (new)
- benchmark/lab/results/README.md
- packages/buggy/tests/unit/benchmark/test_coverage_audit.py (new)

## Out of scope

Changing scoring of agent findings. Adding ground-truth entries that are not in the apps' published challenge lists.

## Tests that must exist and pass

- buckets sum to totals (per class and overall) for the real ground truth.
- an entry whose `verified_by` names a non-existent test fails the audit with a clear error (test with a temp copy).
- a prohibited entry is `excluded`, never `backlog`.
- the committed `coverage.md` equals a fresh render for the same revision except the date line.

## Done when

The audit runs, sums, and the results README matches it.
