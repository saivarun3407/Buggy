# B1 — Coverage stamps: a missing result is never read as clean

Epic: **E02** · Lane: **B** · Depends on: nothing

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

RedAmon stamps coverage per asset (`js_recon_status`, `nuclei_status`: complete / partial / failed) so the agent and the report know what was not checked. Buggy records stage stats per run but nothing per asset, and the report cannot say 'not scanned'.

## Idea

Record, per asset and stage, whether the stage completed, partly completed, failed or was skipped (and why), and surface it.

## Architecture

1. `pipeline/store.py`: new table `coverage(engagement, asset, stage, status, detail, run_id, updated_at, PRIMARY KEY(engagement, asset, stage))`; methods `set_coverage(engagement, asset, stage, status, detail, run_id)`, `coverage(engagement, *, asset=None) -> list[dict]`, `coverage_gaps(engagement) -> list[dict]` (status != `complete`). `status` in `complete | partial | failed | skipped`.
2. `pipeline/pipeline.py`: after each stage, stamp every input asset it handled. Rules: tool returned and parsed -> `complete`; tool timed out or exited non-zero but produced some output -> `partial` with the tool name; tool produced nothing and errored -> `failed`; stage not run because of limits (`passive_only`, `port_scan` off, `disabled_stages`) -> `skipped` with the reason. A cached stage keeps its previous stamp. Stage names are the seven in `STAGES`.
3. `pipeline/query.py`: `summary()` gains `coverage: {complete, partial, failed, skipped}` counts and `coverage_gaps` (first 50). New `ReconQueries.coverage(engagement, asset="")`.
4. `pipeline/report.py`: new section "Not checked" listing gaps grouped by stage with the reason; the Summary table gains a row "Assets with incomplete coverage". When there are gaps, the "Known issues" section starts with one sentence saying the list is not complete.
