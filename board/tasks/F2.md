# F2 — Fact / intent / hint board: agents coordinate through shared state, not chat

Epic: **E07** · Lane: **F** · Depends on: F1

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Cairn (54/54 in a 610-team competition) coordinates role-less workers only through a shared graph: append-only Facts, Intents that link facts and are claimed with a heartbeat lease (a live claim returns 409), and Hints as out-of-band guidance. Buggy's agents coordinate by role-to-role messages, which is where duplicated and dropped work comes from.

## Idea

Implement Cairn's protocol as a small library so the integrator can expose it to agents.

## Architecture

New package `buggy/coordination/`: `board.py` (stdlib only, SQLite `board.sqlite3`).
- `Fact(id "f%04d", engagement, text <= 500, kind (observation|result|origin|goal), evidence: list[str] (capture or record ids), created_by, created_at)`. Append-only: no update or delete API. `add_fact` rejects an exact duplicate text for the engagement (returns the existing id).
- `Intent(id "i%04d", engagement, text, from_facts: list[str] (>= 1, must exist), to_fact (null until concluded), creator, worker, last_heartbeat_at, status (open|claimed|concluded|abandoned), created_at)`.
  - `open_intent(...)`: rejects a near-duplicate of an open intent (same normalised text and same `from_facts` set) by returning the existing one.
  - `claim(intent_id, worker, now)`: succeeds if unclaimed or the lease expired (`intent_timeout`, default 600 s); a live claim by another worker raises `Conflict` (the 409 case); same worker re-claiming = heartbeat.
  - `heartbeat`, `release`.
  - `conclude(intent_id, worker, fact_text, evidence)`: atomically writes a new Fact and sets `to_fact`; only the claiming worker may conclude.
  - `abandon(intent_id, worker, reason)`: writes a Fact of kind `result` "abandoned: <reason>" so the dead end is remembered.
- `Hint(id, engagement, text, author (operator|agent), created_at)`: does not affect facts; newest first.
- `open_work(engagement, now) -> list[Intent]` (unclaimed or expired); `stop(engagement)` clears all claims at once.
- `complete(engagement, worker, from_facts, summary)` writes the `goal` fact via a concluded intent; `reopen(engagement, feedback)` adds a corrective fact and re-opens (external verifier overturning a false completion).
- `snapshot(engagement) -> dict`: facts, intents, hints, counts — the board an agent or the dashboard reads.
All mutating calls go through one transaction each; ids are per engagement.

## Out of scope

A server, agent prompts, MCP registration. Semantic (embedding) dedup.

## Tests that must exist and pass

- facts are append-only (no API to mutate; duplicate text returns the same id).
- intent must reference existing facts; multi-source intents keep all sources.
- claim/heartbeat/lease: second worker gets `Conflict` while live, succeeds after expiry (inject the clock).
- only the claimer can conclude; conclude writes the fact and link atomically (simulate a failure between the two and assert neither is stored).
- `stop` clears claims; `open_work` then lists them.
- `complete` / `reopen` flow.
- concurrency: 8 threads racing to claim the same intent -> exactly one wins.
- engagement isolation: ids and reads never cross engagements.
