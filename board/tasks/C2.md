# C2 — Reflected XSS probe with context analysis

Epic: **E09** · Lane: **C** · Depends on: C1

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Strix confirms XSS in a real browser; Xalgorix bundles dalfox. Buggy has no deterministic XSS check (0 of 3 in the lab baseline).

## Idea

Prove reflection of attacker-controlled markup in an executable context with a unique marker, and say exactly which context.

## Architecture

Follow the existing pattern exactly: a function `name(ctx: Context, params: dict) -> ProbeResult` in a new module under `capture/probes/`, registered with a `ProbeSpec` in `capture/probes/registry.py` (add your entries at the end of the tuple; import your module at the top). All requests go through `ctx.send`. Verdict rules that apply to every probe:
- `vulnerable=True` only with a control that rules out coincidence (stated per probe below).
- `vulnerable=None` ("could not tell") when the baseline request fails, the gateway refuses, or signals conflict. Never guess.
- `evidence` lists the capture ids of baseline, control and proof requests; `details` names which is which.
- `remediation` is specific to the class.
- Payload lists are short and fixed (constants in the module). No destructive payloads: nothing that writes, deletes, sleeps longer than the stated bound, or reads files other than the stated markers.

Module `capture/probes/xss.py`, probe name `xss_reflected`, class `xss`, CWE-79, not state-changing for GET.
Params: `url`, `method`, `parameter`, `location`, `value`, `body`, `headers`.
Algorithm (max 6 requests):
1. Send a harmless unique alphanumeric marker `bg<12 hex>`; if it is not reflected in the body -> `vulnerable=False` with summary "not reflected".
2. Classify each reflection context with a small HTML tokenizer (`html.parser.HTMLParser`): `html_text`, `attribute_quoted` (which quote), `attribute_unquoted`, `script_string` (which quote), `script_code`, `comment`, `url_attribute` (href/src/action), `json_body` (Content-Type is JSON -> not exploitable -> False).
3. For each distinct context send ONE context-specific probe string built around a fresh marker, e.g. html_text: `<bg{m}x>`; attribute_quoted: `"bg{m}=x` / `'bg{m}=x`; script_string: `';bg{m}//`; url_attribute: `javascript:bg{m}`. Vulnerable in that context when the breaking characters come back UNENCODED in the same context (re-tokenize: a new tag named `bg{m}x` exists / a new attribute `bg{m}` exists / the string literal is terminated).
4. Header checks recorded in details: `Content-Type`, `X-Content-Type-Options`, CSP presence (a CSP does not change the verdict, it is reported).
`vulnerable=True` requires step 3 to succeed in at least one context. `details.contexts` lists every context with its verdict. `details.browser_confirmation = "not_run"` (the integrator may add a browser check later; do not call any browser here).
Remediation: contextual output encoding; name the context.

## Out of scope

Stored and DOM XSS. Running a browser. Payloads that execute anything.

## Tests that must exist and pass

Unit: one fake endpoint per context, each in a vulnerable and an encoded (safe) variant — at least 12 cases; plus JSON reflection (False), no reflection (False), reflection only inside an HTML comment (False), unstable page (`None`). Assert the reported context and that probes are capped at 6.
Lab: DVGA or Juice Shop — find one reflected sink in the running lab apps yourself (candidates: Juice Shop `/rest/track-order/<id>` reflects into JSON -> must be reported False by rule 2 with the reason; DVGA pages). If you cannot find a truly reflected-HTML sink in the lab, say so in your report and keep the lab test as the JSON negative control; do not fabricate a positive.

## Done when

Unit tests pass; lab test passes; report states honestly whether a lab positive exists.
