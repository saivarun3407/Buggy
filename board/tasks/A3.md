# A3 — Lite stack: recon and report with two services

Epic: **E01** · Lane: **A** · Depends on: nothing

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Shannon is one image and two commands; Xalgorix is one binary. Buggy starts 13 services (several GB) even for a no-LLM recon run, which needs only the pipeline and its read-only server.

## Idea

A standalone compose file that runs exactly what `hunt --no-agent` needs, with the same isolation rules as the full stack, plus tests that pin those rules.

## Architecture

New file `docker-compose.lite.yml` at the repo root, self-contained (it must NOT require `docker-compose.yml`). Services, copied from the full file with identical hardening (cap_drop ALL, read_only, no-new-privileges, tmpfs, limits):
- `pipeline` (image `buggy-pipeline:${BUGGY_VERSION:-stable}`, network `pipeline-net`, volumes `pipeline_data`, `pipeline_queue`, `${BUGGY_HOME:-~/.buggy}/control:/control:ro`).
- `pipeline-mcp` (same image, entrypoint `python -m buggy.pipeline.mcp_server`, `pipeline_data:ro`, `BUGGY_STACK_MCP_TOKEN` required with the same `:?` message, network `lite-net`).
- `operator` (profile `operator`, image `buggy-pipeline:${BUGGY_VERSION:-stable}`, entrypoint `[]`, command `["python","-m","buggy.cli","--help"]`, mounts control rw / audit rw / workspace rw, env `BUGGY_MCP_RECON_URL=http://pipeline-mcp:9460/mcp`, `BUGGY_ENGAGEMENT_CONTROL=/control`, `BUGGY_ENGAGEMENT_AUDIT=/audit`, `BUGGY_ENGAGEMENT_WORKSPACE=/workspace`, `BUGGY_STACK_MCP_TOKEN`, network `lite-net`, healthcheck disabled).
Networks: `lite-net` (bridge) and `pipeline-net` (bridge). No published ports.

The operator runs from the slim pipeline image, so `buggy.cli.hunt` must import there. Add to `containers/pipeline.Dockerfile` (after the existing COPY lines): COPY of `packages/buggy/buggy/cli`, `packages/buggy/buggy/program`, and a new tiny shim so `hunt --no-agent` works without langchain: verify by reading `cli/hunt.py` imports; anything that imports langchain/langgraph at module load in `cli/hunt.py`, `cli/engage.py`, `cli/_paths.py`, `tools/stack_mcp.py` must become a lazy import inside the function that needs it. `buggy.tools.stack_mcp` imports `langchain_core.tools` at module top: do NOT edit it; instead create `buggy/pipeline/mcp_client.py` with `call_mcp_sync(server, tool, args)` and `server_configured(server)` implemented with the `mcp` SDK only (copy the logic, keep the same env names and `client_headers()`), and make `cli/hunt.py::_recon` / `recon_available` use it. `stack_mcp.py` keeps working unchanged.

Also add `tests/test_compose_lite.py` (skip if the docker CLI is absent), modelled on `tests/test_compose_network_isolation.py::_rendered_compose`.

## Out of scope

The Go launcher (task A4). The full compose file. Building images.

## Tests that must exist and pass

- `test_compose_lite.py`: renders with `docker compose -f docker-compose.lite.yml config`; exactly the three services; no published ports; `pipeline` is only on `pipeline-net`; `pipeline-mcp` mounts the store read-only; control is read-only for both servers and writable only for `operator`; rendering fails without `BUGGY_STACK_MCP_TOKEN`; no service carries `*_API_KEY` or `LITELLM*`.
- `test_mcp_client.py`: against a real FastMCP server started on a free port with `buggy.pipeline.mcp_http.build_app` (copy the `_Server` helper from `tests/unit/stack_mcp/test_stack_mcp.py`): a call with the token works, without it returns `{"error": ...}`; unconfigured server -> `server_configured` is False.
- Import guard: a subprocess test that blocks `langchain`, `langchain_core`, `langgraph` in `sys.modules` (set them to None) and then imports `buggy.cli.hunt` and runs `hunt.main([... "--plan-only", "--yes"])` successfully in a tmp dir.
- Existing `tests/unit/cli/test_hunt.py` still passes.

## Done when

`hunt --plan-only` and `hunt --no-agent` paths import and run with langchain blocked; the lite compose file renders and passes its invariants.
