# F5 — Program brief: where to look first on a bounty program

Epic: **E13** · Lane: **F** · Depends on: F4

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

h1-brain's `hack(handle)` returns fresh scope, 'Weakness Types That Worked', 'Untouched Scope' and suggested attack vectors from the hunter's own HackerOne history and disclosed reports. Buggy imports scope and rules but gives no guidance on where effort pays.

## Idea

A deterministic briefing built from data the operator already has: the imported program, the recon store, past findings, and (optionally) an operator-supplied export of their reports.

## Architecture

New `program/brief.py`:
- Inputs: `program` (program.json), `recon` (`{records_by_type}` summaries: hosts, services, technologies, api operations, parameters with hints), `findings` (list of Finding dicts for this engagement and, if available, other engagements on the same program handle), `history` (optional operator file `control/<engagement>/report-history.json`: `[{"id", "title", "weakness", "asset", "state": "resolved|duplicate|informative|not-applicable|triaged|new", "bounty": number|null, "created_at"}]` — the shape of a HackerOne report export reduced to non-sensitive fields).
- `build_brief(...) -> dict`:
  - `scope_summary`: in-scope assets with `max_severity` cap and whether bounty-eligible.
  - `untouched_scope`: in-scope hosts with zero captures and zero findings (needs `captured_hosts: set[str]` input), most surface first (count of endpoints + operations).
  - `what_paid`: weaknesses from `history` with state resolved/triaged and a bounty, by count and total.
  - `what_did_not`: weaknesses that came back duplicate/informative/n-a (avoid these here).
  - `excluded`: the program's excluded classes and banned techniques.
  - `suggested_focus`: ranked list of `{class, where, why, probe}` combining: recon test candidates (from `pipeline.report.rank_candidates`) boosted when the class is in `what_paid`, dropped when excluded, down-weighted when in `what_did_not`; each `why` cites the data that produced it.
  - `duplicates_risk`: findings in the current engagement whose class+asset match a `history` item in state `duplicate` or `resolved`.
- `to_markdown(brief) -> str`.
- `cli/program.py`: `buggy-cli program brief <engagement> [--history FILE] [--json]` reading control dir + recon/captures/findings through injected fetchers (same pattern as `cli/status.py`: a `fetch(server, tool, args)` callable; unavailable sources degrade, never crash). Writes `control/<engagement>/program-brief.md`.
No network calls to bounty platforms in this task.

## Out of scope

Fetching report history from HackerOne (a later task can add it behind operator credentials). Changing the importer.

## Tests that must exist and pass

- fixture program + recon + history -> exact expected sections; a class that paid before is ranked above one that did not; an excluded class never appears in `suggested_focus`.
- untouched scope ordering.
- every `why` string cites its source ("paid 3 times on this program", "12 operations with id-like parameters").
- no history file -> brief still builds, with those sections marked "no history supplied".
- duplicates risk detection.
- CLI degrades when recon/captures/findings fetchers fail.
