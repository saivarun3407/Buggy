# D2 — Authorization matrix: every endpoint against every identity

Epic: **E09** · Lane: **D** · Depends on: D1

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Access control is the highest-paying class and it is mechanical to test once identities exist: request each object as owner, as another user, and anonymously, and compare. Shannon has an Authorization agent; a matrix makes the same check exhaustive and cheap.

## Idea

A deterministic runner that produces an endpoint x identity matrix and flags cells where a non-owner gets the owner's data.

## Architecture

New module `capture/authz_matrix.py`:
`run_matrix(gateway, sessions, engagement, urls, *, identities, owners=None, include_anonymous=True, markers=None, max_requests=300) -> dict`
- GET/HEAD only. For each URL: request once per identity (+ anonymous). `owners` maps url -> identity name; when absent, use each identity's `owner_of` patterns (exact URL or prefix ending in `*`); a URL with no known owner is compared pairwise only for "same private content for everyone".
- Per cell: `{status, bytes, sha256, capture_id, similarity_to_owner}` using `probes.base.similarity`.
- Verdict per URL:
  - `broken_access` — a non-owner (or anonymous) cell has status 2xx AND (similarity_to_owner >= 0.95 OR any owner marker string present) AND the owner cell itself is 2xx;
  - `enforced` — non-owner cells are 401/403/404 or clearly different (< 0.5) and marker-free;
  - `public` — anonymous gets the same content as everyone and no marker is defined (not a finding; listed separately);
  - `inconclusive` — owner cell failed, or the page is unstable (owner requested twice differs).
- Output: `{"matrix": {url: {identity: cell}}, "verdicts": {url: {...}}, "candidates": [Finding-shaped dicts per CONTRACTS.md for every broken_access, with `assertions` citing the owner and attacker captures and `expect.same_as`/`body_contains`], "requests": n, "truncated": bool}`.
- Rate limit and scope are the gateway's; stop at `max_requests` and set `truncated`.

## Out of scope

State-changing methods. Registering an MCP tool. Guessing object ids (the caller supplies URLs).

## Tests that must exist and pass

Unit (fake origin with three users): an endpoint that checks ownership (`enforced`), one that does not (`broken_access`, candidate emitted with both capture ids), a public endpoint (`public`), an owner-only page with volatile content (`inconclusive`), anonymous access to a private object (`broken_access`), `max_requests` truncation, a POST-only URL is skipped with a reason.
Lab: Juice Shop — create two accounts through the gateway, each with a basket; identities built in the test with `static` headers; `/rest/basket/<id>` must come out `broken_access` for the other user's basket; `/rest/user/whoami` must not be a candidate.

## Done when

Unit and lab tests pass.
