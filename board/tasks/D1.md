# D1 — Identities: declarative login and multi-role sessions the agent never sees

Epic: **E09** · Lane: **D** · Depends on: nothing

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Shannon configures login declaratively (`login_flow` steps, TOTP, `success_condition`) and validates it before testing. Authenticated, multi-role testing is where IDOR and access-control bugs live; today Buggy's probes need the agent to hold raw tokens.

## Idea

The operator declares test accounts once. The gateway logs in, keeps the session, and attaches it when a request names an identity. Agents refer to identities by name and never receive credentials or tokens.

## Architecture

New module `capture/identities.py`:
- File `secrets/<engagement>/identities.json` (root from `BUGGY_SECRETS_ROOT`, default `/secrets`; operator-written, never mounted into agent-facing containers):
```json
{"identities": [{"name": "alice", "role": "user", "owner_of": ["https://app/api/orders/1001"],
  "static": {"headers": {"Authorization": "Bearer ..."}, "cookies": {"sid": "..."}},
  "login": {"request": {"method": "POST", "url": "https://app/rest/user/login", "headers": {"Content-Type": "application/json"},
                         "body": "{\"email\": \"{username}\", \"password\": \"{password}\", \"otp\": \"{totp}\"}"},
            "credentials": {"username": "...", "password": "...", "totp_secret": "BASE32"},
            "extract": [{"name": "token", "from": "json", "path": "authentication.token"},
                        {"name": "sid", "from": "cookie", "cookie": "sid"},
                        {"name": "csrf", "from": "header", "header": "X-CSRF"},
                        {"name": "x", "from": "regex", "pattern": "token=([A-Za-z0-9._-]+)"}],
            "apply": {"headers": {"Authorization": "Bearer {token}"}, "cookies": {"sid": "{sid}"}},
            "success": {"status": 200, "body_contains": "authentication"}}}]}
```
- `IdentityStore(secrets_root)`: `load(engagement) -> dict[name, Identity]`, validation errors name the field. `public(engagement) -> list[{name, role, owner_of, kind: static|login}]` (no secrets).
- `SessionManager(gateway, store)`: `auth_for(engagement, name) -> (headers, cookies)`; performs the login through `gateway.send(..., probe="login")` on first use (login requests are exempt from the approval hold: add a parameter `internal=True` to `CaptureGateway.send` that skips ONLY the approval check, is not reachable from any MCP tool argument, and is recorded in the ledger as `internal_login`); caches per engagement+name; `invalidate()`; re-login once when a later response is 401.
- TOTP: RFC 6238 SHA-1, 30 s, 6 digits, implemented with `hmac`/`struct`/`base64` (test against the RFC vectors).
- `CaptureGateway.send(..., identity: str = "")`: when set, merge the identity's headers/cookies into the request (identity values win over caller headers of the same name) and record `identity` on the capture (new column `identity TEXT DEFAULT ''` with a migration that adds it if missing). Sensitive values stay redacted by `Capture.detail()`; add `Cookie` and `Set-Cookie` and any header named in an identity's `apply` to the redaction set for that capture.
- `Roots` gains `secrets: Path` (from env; default `/secrets`).

## Out of scope

Browser-driven logins, OAuth redirects, SSO. MCP tool registration. Compose mounts (integrator).

## Tests that must exist and pass

- TOTP matches RFC 6238 test vectors.
- login flow: fake origin issues a token on correct credentials; `auth_for` returns the applied header; the token is cached (one login for many sends); a 401 later triggers exactly one re-login; wrong `success` condition -> clear error and no session.
- each `extract` source (json path, cookie, header, regex).
- `gateway.send(identity="alice")` attaches the session; the stored capture has `identity="alice"`; `Capture.detail()` shows `<redacted>` for the auth header and cookie; `public()` contains no secret, no token, no password (assert by searching the JSON for the fixture secrets).
- a caller cannot skip approval: `internal` is not accepted by `CaptureTools.http_send` (assert the MCP-facing class has no such parameter) and a state-changing non-login request with approvals required is still held.
- unknown identity -> `GatewayRefusal("UNKNOWN_IDENTITY")`.
- malformed file -> validation error naming the field.
