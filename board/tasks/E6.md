# E6 — Retest: prove a fix with the same proof

Epic: **E11** · Lane: **E** · Depends on: E5

Read `board/AGENT_RULES.md` and `board/CONTRACTS.md` first.

## Why (who does this well, and what Buggy lacks)

Shannon Pro and Strix Cloud sell 'retest after fix'; RedAmon opens fix PRs. The open-source tools here do not close the loop. With assertions stored per finding, a retest is cheap and exact.

## Idea

Re-run a verified finding's assertions later and record whether it is fixed, still vulnerable, or cannot be determined.

## Architecture

New `findings/retest.py`:
- `retest(service, engagement, finding_id, *, allow_state_change=False) -> dict`: runs the verifier against the stored assertions without changing the finding's `status`; result `still_vulnerable` (all assertions pass), `fixed` (the proof assertions now fail in the safe direction: attacker gets 401/403/404, or the proof marker is gone, on two consecutive attempts), `inconclusive` (anything else: errors, unstable, state-changing without approval). Appends a `retest` event with the outcome and the new capture ids, and sets `finding.retest = {at, outcome, capture_ids}`.
- A `fixed` finding gets `fixed_at`; a later `still_vulnerable` clears it and records a `regressed` event.
- `cli/retest.py`: `buggy-cli retest <engagement> [<finding-id> | --all-verified] [--json]` using a `FindingService` built from `Roots.from_env()` (operator side or inside the capture service); prints one line per finding; exit 0 all fixed, 10 any still vulnerable, 3 any inconclusive (vulnerable wins).
The definition of "safe direction" is explicit per expectation type and documented in the module docstring.

## Out of scope

Generating fixes or pull requests.

## Tests that must exist and pass

- vulnerable fake -> `still_vulnerable`; patched fake (403) -> `fixed` only after two consistent attempts; first attempt 403 then 200 -> `inconclusive` (flaky); regression after fixed -> event `regressed`.
- state-changing proof without approval -> `inconclusive`, nothing sent.
- CLI exit-code matrix and `--json` shape.
- status of the finding is unchanged by a retest (assert).

## Done when

`tests/unit/findings` and the CLI test green.
