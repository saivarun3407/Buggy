# Ideas from how people build hackbots

Source: [secnotes.fyi/hackbot](https://secnotes.fyi/hackbot/), 86 cards, each summarising
one practitioner post, vendor write-up or paper on building an AI hacking agent, with the
idea worth taking from it. Below: each card's suggestion as the site states it, its source,
and where Buggy stands (our assessment). Read the source for the argument; this is a checklist.

Totals: 22 have, 41 partly, 21 missing, 2 not for Buggy (native-code fuzzing).

## What Buggy should take next

The missing ideas that matter most, grouped into the work that would close them. Each is a
card on the board (epic E17).

| Card | Work | Ideas it closes |
|---|---|---|
| B1 | Evaluation: run the lab benchmark and the Juice Shop scoreboard with stage-level scores (recon, lead, proof, report), scope adherence reported apart from results, failure labels per run, and a plain-agent baseline at equal budget | 11, 12, 24, 27, 31, 55, 67, 74, 75, 78, 83 |
| B2 | Halt switch and shared budget: an operator halt that every tool call checks, and a revocable lease per agent run | 28, 43, 65 |
| B3 | Ruled-out ledger: every lead tried and dropped is kept with the reason (blocked, refused, no signal), shown to the next agent so it does not repeat it, and failed routes are kept per technique, not per attempt | 44, 54, 76 |
| B4 | Keep going: when the agent says it is done with budget left, it gets the open leads again; restarts label earlier 'cannot be done' as unproven; several short attempts instead of one long one | 69, 80 |
| B5 | Disprover pass: a separate skeptic (another model) argues each agent-made finding is false before it is graded; disagreement means undetermined | 30, 38, 45, 46, 59 |
| B6 | Cost and overhead: tokens and time per agent run, per stage and spent on sign-in, next to the findings | 3, 23, 59, 63, 65 |
| B7 | Trace review: a tool that samples agent traces and flags loops, dead ends, and claims made without a matching tool call; refusal counts per run as an injection sign | 17, 18, 34 |
| B8 | Skill versions: a digest per skill in a lockfile, and a skill change used only after it passes a check run | 39 |
| B9 | Recovered source: source maps found by recon are rebuilt and scanned with static rules; hits become leads that still need a live proof | 21, 33, 35 |
| B10 | Fix breaking and variants: retest tries variants of the payload against a fix, and a proven bug seeds a search for its siblings elsewhere | 29, 70 |
| B11 | Invariants and chaining: a finding cites the rule it breaks and its entry point; findings form a needs-and-gives graph that suggests chains | 42, 82 |
| B12 | Expiring decisions: a held or discarded finding gets a review date and comes back | 15 |

## Every idea

| 1 | Basic | **The known playbook is finite.** Encode one bug class as a reusable brief, and treat unknown or novel techniques as a human-led layer rather than something the bot is assumed to invent. | [Joseph Thacker (rez0)](https://josephthacker.com/ai/2023/11/08/ai-hacking-agents.html) | Have | One skill per bug class (162 web skills); leads name their skills; novel attacks stay with the agent and the operator. |
| 2 | Basic | **Put the model where the traffic already is.** Start by giving the model access to the traffic and one repeating chore in your existing proxy, rather than standing up a separate autonomous stack. | [Andrew Pratt, Caido](https://www.caido.io/blog/2026-03-24-ai-enhanced-hacking/) | Partly | The agent works from captured traffic through the gateway; no Burp or Caido plugin. |
| 3 | Basic | **A heavy harness can get in the way.** Default to a lighter harness as models improve, keep a human in the validation loop, and budget for token spend as a cost of competing. | [Luke Stephens (hakluke)](https://hakluke.com/are-bug-bounties-cooked) | Partly | A person approves writes and submits reports; tool-call cap per run. Token spend of Claude Code runs is not tracked. |
| 4 | Basic | **Point the model, then make it build tools.** Keep a library of deterministic tools for repeatable recon and checks, and save the model for aiming those tools at unusual surfaces. | [Luke Stephens (hakluke)](https://hakluke.com/how-to-start-or-come-back-to-bug-bounties-in-2026) | Have | Core rule: recon, probes, re-proof, grading and reports are code; the agent aims them and builds recipes. |
| 5 | Basic | **An AI pentest still has the same four stages.** Split the bot into four stages, and never let the agent that found an issue be the one that marks it confirmed. | [XBOW Team](https://xbow.com/blog/core-components-ai-pentesting-framework) | Have | Recon, testing, independent re-proof (finding_verify), grading. The agent cannot mark its own finding verified. |
| 6 | Basic | **Share state, not transcripts.** A parsed engagement-state store, plus a critic that is the only path into the report. | [Zakaria Bouazza](https://blog.zakaria.lu/a-pentest-agent-fleet-against-my-own-site-what-the-architecture-got-right) | Have | Recon store and findings store are the shared state; only verified and graded findings reach the report. |
| 7 | Basic | **The model is the brain, your code is the hands.** Keep scope checks and traffic approval in our code, outside the model, and treat every tool result as untrusted input. | [NotHoly](https://notholy.com/en/blog/build-a-hackbot-part-1-architecture) | Have | The evidence gateway checks scope, approvals and rate in code; tool and web output is marked as data. |
| 8 | Basic | **One agent, one job, one context pack.** Split agents by narrow bug sub-type, each with its own cleaned knowledge pack, and keep grunt work in plain scripts. | [Jason Haddix, Arcanum Security](https://arcanum-sec.com/blog/hackbots/) | Partly | Skills per bug class and narrow probes; Claude Code runs as one agent, not one per bug sub-type. |
| 9 | Basic | **Static leads become dynamic tests.** Pass structured findings between stages, require a second agent to confirm before escalating, and lock down the security agent itself. | [Rajesh TV, Deriv (Fortress AI)](https://derivai.substack.com/p/ai-agent-security-offensive-security-swarm) | Have | Structured leads and findings; independent verifier; the agent has no shell and no direct network path. |
| 10 | Basic | **Tiny, boring tools for the agent, with a log it can't edit.** Wrap whole workflows as typed, lean tools, and keep an append-only log written by the tools so 'confirmed' can be checked against what actually happened. | [Luke (hakluke) Stephens, Detectify](https://blog.detectify.com/best-practices/why-im-building-my-hacking-agent-out-of-tiny-boring-tools/) | Have | Typed tools; the gateway's ledger and captures are written by code, and the verifier checks them. |
| 11 | Basic | **Start from a method that already works.** Benchmark each agent step against the deterministic script it replaces, and keep the agent only where it wins. | [Bronxi, Bugcrowd (guest post)](https://www.bugcrowd.com/blog/what-i-learned-building-ai-agents-for-bug-bounty-hunting/) | Missing | No measurement of agent steps against the code they could replace. |
| 12 | Basic | **Contamination is not the only way agents cheat evaluations.** Review evaluation transcripts for both contamination and grader gaming, and treat published cheat rates as lower bounds. | [Maia Hamin and Benjamin Edelman, NIST CAISI](https://www.nist.gov/caissi/cheating-ai-agent-evaluations) | Missing | No agent evaluation yet, so no transcript review for gaming. |
| 13 | Intermediate | **Mix the models in one conversation.** Try alternating models inside one shared thread, without adding extra calls, and measure whether the mix beats any single model. | [Albert Ziegler, XBOW](https://xbow.com/blog/alloy-agents) | Missing | One model per run. |
| 14 | Intermediate | **The harness sets the ceiling.** When a new model disappoints, change how agents coordinate and share context before you assume the model is the limit. | [Pedro Conde, Ethiack](https://ethiack.com/info-hub/blog/ai-pentesting-harness-matters) | Partly | Harness changes are measured on the practice apps; no systematic harness comparison. |
| 15 | Intermediate | **Only keep findings you would actually review.** Require evidence before a finding is filed, and make every ignore decision expire so it has to be revisited. | [Jameson Lopp, Casa](https://blog.casa.io/how-built-reliable-ai-pentest/) | Partly | No finding without a capture; no 'ignore' decision that expires and must be revisited. |
| 16 | Intermediate | **Shrink the maze the agent walks.** Split the job into sub-agents, and replace a generic shell with a small set of tools that match the sub-task. | [Xint, Theori](https://theori.io/blog/building-effective-llm-agents-63446) | Have | No shell; a small set of typed tools per task (probes, recipes, http_send, browser). |
| 17 | Intermediate | **Debug the bot by reading its traces.** Keep full agent traces and regularly read a sample, looking for loops, dead ends, and invented observations. | [Xint, Theori](https://theori.io/blog/exploring-traces-63950) | Partly | The bridge logs every tool call; nobody samples traces for loops or invented observations. |
| 18 | Intermediate | **The agent needs tools it can stay inside.** Give the bot a real interactive debugger and connection tool, and log whether a tool was actually called before you trust what it claims to have seen. | [Talor Abramovich et al.](https://arxiv.org/abs/2409.16165) | Partly | Tool calls are logged and assertions must cite real capture ids; no interactive debugger tool. |
| 19 | Intermediate | **Security work is not a short coding loop.** Persist state across long, pauseable tasks, and run tool use in an isolated sandbox with an explicit allow-list of what the bot can touch. | [Rachel Benson, ProjectDiscovery](https://projectdiscovery.io/blog/introducing-neo) | Have | Engagement state persists; hunt --resume; requests only through the scoped gateway. |
| 20 | Intermediate | **A staged pipeline that hands work to the next stage.** Give the bot explicit phases that hand structured findings to the next one, and let it save and resume a session. | [Gelei Deng et al.](https://github.com/GreyDGL/PentestGPT) | Have | Staged hunt with structured hand-off and resume. |
| 21 | Intermediate | **No finding without a live proof.** Keep two streams of candidates (code review and live recon), merge them, and only promote a finding after a live, reproducible proof. Put scope and login rules in config. | [Keygraph](https://github.com/KeygraphHQ/shannon) | Partly | Live proof required and scope and logins in config; no code-review stream of candidates. |
| 22 | Intermediate | **A team of agents inside a sandbox.** Run the agents in an isolated sandbox, let them share work as a team, and limit CI scans to the changed files. | [Strix](https://github.com/usestrix/strix) | Partly | Isolated containers and retest of fixed findings; no scan limited to changed files. |
| 23 | Intermediate | **Put the right model in the right role.** Give planning and execution to different models, and track cost alongside accuracy so a cheaper model can do the hands-on work. | [Pedro Conde, Ethiack](https://ethiack.com/info-hub/research/strategy-is-key-evaluating-the-pentesting-skills-of-frontier-LLMs) | Partly | Built-in agents have a model per role; Claude Code runs one model; cost is not tracked next to accuracy. |
| 24 | Intermediate | **Grade the steps, not just the flag.** Test the bot on a fixed set of tasks with step-by-step subgoals, not only on whether it finished the whole chain. | [Andy K. Zhang et al.](https://cybench.github.io/) | Missing | The lab benchmark scores found bugs, not sub-goals. |
| 25 | Intermediate | **The model proposes, deterministic code disposes.** Scope as signed data checked on every tool call, never just a system-prompt line. | [UNST33R](https://unst33r.si/blog/bounded-llm-penetration-testing-agent) | Partly | Scope is checked on every request in code and lives under an operator-only root; it is not signed. |
| 26 | Intermediate | **Guardrails that redirect instead of just refusing.** A deny-list proxy at the action boundary, backed by a judge that explains how to proceed safely. | [Dev Leibowitz, Novee](https://novee.security/blog/safety-in-depth-layered-guardrails-for-autonomous-pentesting/) | Partly | Refusals name a code and, for some, the next step (read this skill, ask for approval); no judge that proposes a safe alternative. |
| 27 | Intermediate | **A hierarchical pentest agent with a benchmark behind it.** Scope tools per agent and use machine-verifiable success conditions for every benchmark target. | [HackerOne, Pawan Agarwal](https://www.hackerone.com/blog/agentic-ptaas-security-architecture) | Partly | Lab ground truth exists for four practice apps; not run since the latest changes. |
| 28 | Intermediate | **How controls break when a pentest splits across agents.** Stamp each work lease with a halt epoch and a shared budget, and check both before every tool call. | [OWASP APTS](https://owasp.github.io/APTS/standard/appendix/Multi_Agent_Coordination.html) | Missing | Call cap per run and lead leases exist; no halt switch or shared budget checked before every tool call. |
| 29 | Intermediate | **Fresh-context specialists and a patch-then-break loop.** Pass state between stages through a graph, not transcripts, and add a stage that tries to break your own proposed fix. | [Decepticon docs](https://docs.decepticon.red/en/vision/target-architecture) | Missing | Retest re-runs the proof after a fix; nothing tries to break the fix with variants. |
| 30 | Intermediate | **A validator whose job is to say no.** A fail-closed scope gate with tools off by default, plus a separate disprover agent before anything is reported. | [Philip Sørensen](https://philipsoerensen.com/blog/building-a-bug-bounty-hackbot) | Partly | Fail-closed scope gate and deterministic verifier; no separate disprover pass. |
| 31 | Intermediate | **The hypothesis is easy, the proof is hard.** Measure and improve the hypothesis-to-proof step, not just the bug-spotting step. | [arXiv 2611.06257 (García-Carrasco et al.)](https://arxiv.org/abs/2611.06257) | Missing | Not measured: how many leads become proofs, and where they fail. |
| 32 | Intermediate | **Code gathers; the agent judges.** Spend model calls only on changed evidence bundles, and have the model write validated proposals that code and a human admit. | [Viral Maniar, Harsh Maniar & Mike Chen, Preemptive Cyber Security](https://preemptivecybersec.com/pages/blog/build-a-hackbot-ai-bug-bounty.html) | Partly | Approvals gate writes; recon keeps diffs; agent runs are not limited to changed evidence. |
| 33 | Intermediate | **Recovered source maps, CodeQL first, AI second.** Let static queries pick the candidates and the model reason over their output, then require a dynamic check before anything counts. | [Sky, RapidDNS](https://blog.rapiddns.io/posts/ai-bug-bounty-pipeline/) | Partly | Recon finds published source maps; recovered source is not analysed statically. |
| 34 | Intermediate | **Scope in the prompt is a suggestion.** Declare mutating, blast radius and approval on every tool, and watch policy denials per run as an early sign of injection. | [Peyush Baranwal, Adayptus](https://www.adayptus.com/blog/ai-assisted-penetration-testing-agent) | Partly | Probes declare state_changing and need approval; refusals per run are not monitored as an injection sign. |
| 35 | Intermediate | **Same model, with and without the source.** Give the reasoning stage read access to source, and test the validator's own checks, since a buggy proof check misfiles real bugs. | [Amr Ayoub](https://amrayoub.dev/the-ai-pentester-that-reads-your-code/) | Partly | Verifier and probes have their own tests; the agent has no source access. |
| 36 | Intermediate | **A finished run is not a finished report.** Checkpoint long runs, build reports deterministically from saved findings, and reject any finding whose evidence doesn't show the claim. | [David Uhlmann](https://daviduhlmann.cloud/blog/automated-pen-testing-with-autonomous-ai-agents/) | Have | Runs resume; reports are built by code from saved findings; findings without matching evidence are rejected. |
| 37 | Intermediate | **The LLM is the operator, not the executor.** Keep the model out of the request loop, and require a marker, a baseline differential and a clean control before a finding counts. | [johnmatrix](https://johnmatrix.org/ai-research/building-an-autonomous-pentest-agent/) | Partly | Probes use a marker, a baseline and a control; the agent can still send requests itself with http_send. |
| 38 | Intermediate | **Fresh sessions, external memory, budgets in code.** Enforce budgets from outside the model, and verify findings in a fresh session on a different model. | [Jake Garnier](https://jakegarnier.com/blog/hackbot-architecture) | Partly | Budgets are enforced in code; verification is code, not a second model session. |
| 39 | Intermediate | **Versioned, signed, evaluated pentest skills.** Version our skills with digests and lockfiles, and promote a change only after it passes checks on fresh runs. | [zilbon, Tahr](https://blog.tahr.one/posts/how-we-build-test-and-share-offensive-ai-capabilities) | Missing | Skills have no version, digest or evaluation before a change is used. |
| 40 | Intermediate | **The finder makes leads, the triager treats them as allegations.** Set a proof gate per bug class, default disagreement to undetermined, and never count 'it built' as reproduction. | [Antonio Viggiano, Monad Foundation](https://monad.xyz/blog/monad-bugfinder) | Partly | A proof rule per probe; unclear results are 'undecided' or 'inconclusive'. | 41 | Intermediate | **Don't give the model jobs that have right answers.** Keep routing, halting, logging and success checks in code, and verify every 'objective achieved' claim against real target state. | [Jay Hawkins, Centaur Security Labs](https://centaursecuritylabs.com/research/stochastic-trap/) | Have | Routing, stopping, logging and success checks are code; a claim counts only after re-proof against the target. |
| 42 | Intermediate | **Threat packs: give the hunting agent the invariants.** Require every finding to cite an invariant and an entry point before reproduction, and track stable detection across repeated runs. | [Lankford, Meen and Peronnet, Datadog](https://www.datadoghq.com/blog/datadogs-agentic-vulnerability-hunting-system/) | Missing | Findings do not cite an invariant; detection is not tracked across repeated runs. |
| 43 | Intermediate | **Scope is enforced by a proxy, not a prompt.** Put the agent behind a scope proxy that fails closed with a revocable lease, and test it with redirect and rebinding cases. | [rootzero](https://rootzero.eu/en/research/offensive-agents-scope-guardrails/) | Partly | The gateway fails closed and never follows a redirect off scope; no revocable lease for a running agent. |
| 44 | Intermediate | **What makes an offensive harness work, from a T3MP3ST teardown.** Give the bot an oracle that proves impact from the target's behaviour, and keep a ledger of ruled-out leads so it doesn't repeat them. | [Ilya Kabanov, The Weather Report](https://theweatherreport.ai/posts/t3mp3st-pliny-bug-hunting-harness/) | Partly | Proof comes from the target's behaviour; leads that were tried and ruled out are not kept with a reason. |
| 45 | Intermediate | **A finder that is never allowed to confirm its own finding.** Make the verifier a separate agent that starts from 'false positive', has a retry verdict for blocked tests, and must attach proof to anything it confirms. | [ProjectDiscovery Neo docs (vendor documentation)](https://docs.neo.projectdiscovery.io/concepts/verification) | Have | The verifier starts from not proven, has inconclusive for blocked tests, and stores the proof. |
| 46 | Intermediate | **A judge that fails closed.** Use a judge on a different model with a heartbeat, and keep real credentials behind a proxy, never inside the agent. | [Dan Scofield, Shopify](https://shopify.engineering/cyber-chaos-monkey) | Partly | Credentials stay behind the gateway; no judge model with a heartbeat. |
| 47 | Intermediate | **Price operational risk into every action.** Score each action on both value and disruption risk, with an adjustable caution setting for each engagement. | [arXiv 2611.25809 (Pironti et al.)](https://arxiv.org/abs/2611.25809) | Partly | Writes need approval; no per-action risk score or caution dial. |

| 49 | Intermediate | **Configuration beats capability.** Keep the validator as separate deterministic code the detecting model can't influence, and route each task to the model that fits it. | [Elliot Belt (Felix Billières)](https://felixbillieres.github.io/posts/llm-bug-bounty-pipeline-2026/) | Have | The verifier and grader are separate code the agent cannot influence. |
